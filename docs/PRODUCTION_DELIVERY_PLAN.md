# Production delivery sequence

Target: a private aviation research portal using the historical public dataset and clearly synthetic operational scenarios. This is not an authorized airline control system. Continue locally while preparing for a future cloud choice; no paid resources, merge or deployment is authorized by this plan alone. Preserve all 64 workspaces, existing accounts, data, frozen model experiments and previous evidence.

The original production assessment retains 24 open requirements. Its dated entries must be reconciled with newer local evidence rather than interpreted as current missing-code counts. No requirement becomes production accepted just because a local test or PR passes.

## First foundation increment

The request-correlation change introduces server-generated API request IDs, allowlisted structured response-preparation events, generic correlated unhandled-error responses and validated proxy ID forwarding. See `REQUEST_CORRELATION.md` for execution and limitations. This is one local foundation increment, not completion of Phase 1 or protected audit.

The second local foundation increment is [configuration and secret-reference preflight](CONFIGURATION_PREFLIGHT.md): strict local settings, rejected unsupported security/secret declarations, safe diagnostic commands and startup admission checks. This validates supported environment settings; it does not implement a secret provider, managed identity or HTTPS.

The third local foundation increment defines the [HTTPS, identity and database boundaries](FOUNDATION_BOUNDARIES.md) and adds an explicit offline schema inspection command. It catches incomplete migration history and selected missing structures without migrating state. It is not a live startup or automated release gate. HTTPS, managed identity, database availability and the first release's users/workload/service objectives remain unimplemented or undecided. The cloud/provider decision remains deferred under the user's local-first preference. Production profiles remain fail-closed until their required controls exist.

The fourth local foundation increment adds the [startup migration-history guard](STARTUP_MIGRATION_GUARD.md). Initialization and health projections reject incomplete or unsupported histories; supported older histories retain the existing transactional upgrade path. This is narrower than complete schema validation, database high availability or a production release gate.

The fifth local foundation increment adds [transactional security events](LOCAL_SECURITY_AUDIT.md), an admin-only read endpoint and schema migration 8. Event writes commit with the covered identity actions; failures roll them back. Recovery inventory and selected state-contract fingerprints include the audit state and identity modules. This changes schema/rollback compatibility and requires new isolated deployment/recovery qualification before release. Independent protected audit storage and comprehensive coverage remain open.

The sixth local foundation increment adds a [repeatable synthetic schema-8 upgrade/recovery rehearsal](SCHEMA8_REHEARSAL.md), contiguous-history backup verification and rollback metadata rejection before Docker access. It verifies isolated database return points, not a primary deployment or image/model parity. The schema-7 return point predates all schema-8 writes; its data-loss implications remain a release decision.

The seventh local foundation increment adds the [audit schema/connection guard](AUDIT_CONTRACT_GUARD.md). Specified missing or altered safeguards prevent startup, covered identity writes, healthy audit projections and backup/offline qualification. Schema remains 8, with no automatic repair. This remains local structural/configuration evidence, not independently protected or authenticated audit contents.

The eighth local foundation increment adds [audited restore-session revocation and unfinished-restore interlocks](AUDITED_RESTORE.md). The revocation/event commit is atomic; the entire multi-step restore is not. Failed copies remain marked and normal startup, backup/verification and the receipt projection refuse them. Schema remains 8; directory publication, independent recovery and actual-image qualification remain open.

The ninth local foundation increment adds a [read-only restore evidence verifier](RESTORE_EVIDENCE_VERIFICATION.md) for fresh quiescent offline copies, and integrates it into the synthetic rehearsal. It streams retained rows and compares manifest/receipt/event/artifact bindings without modifying inputs. This is consistency evidence, not authenticated origin, live-health policy, active-agent recovery verification or production qualification.

## Data-platform continuation

The first new data-platform increment adds [bounded private-copy ingestion and atomic replay handling](IMPORT_SAFETY.md), with a synthetic-only drill linking a stored fixture row to its import ledger and archive hash. Existing selected-field normalization and real BTS labels remain unchanged; no external archive or primary database is imported by the drill. Concurrent small-fixture replays and rollback are measured locally, not representative-scale ingestion or source authorization. Foundation and production acceptance remain open while work proceeds on data reliability.

The second new data-platform increment adds [availability-time weather feature joins](TIME_SAFE_FEATURES.md). Research queries select only same-airport observations recorded as available by the decision time; stale or unavailable values remain explicit. A synthetic-only case records per-query provenance and verifies delayed-report exclusion. Authorized weather ingestion, UTC/station mapping, representative scale and an independent chronological model experiment remain open. Existing frozen models and dashboard behavior are unchanged.

The third new data-platform increment adds [explicit local-schedule to UTC decision conversion](DECISION_TIMES.md), including normalized `2400`, mapping validity intervals and exclusion of ambiguous/nonexistent civil times. An integrated synthetic trace feeds the ready UTC decisions into the availability-time weather join and retains timezone version/hash evidence. Real airport/station references, external weather ingestion, representative resource measurements and independent model evaluation remain open.

The fourth new data-platform increment adds [synthetic feature-pipeline resource measurements](FEATURE_RESOURCE_MEASUREMENT.md) at fixed smoke and current admitted-count workloads. It records phase time/CPU, traced Python allocations, deterministic record fingerprints and sampled independent selection checks. Synthetic allocation measurements are not whole-process memory, representative airline load, ingestion scheduling or production capacity qualification.

The fifth new data-platform increment adds [resumable synthetic incremental ingestion](RESUMABLE_SYNTHETIC_INGESTION.md): a separate durable case queue, single-host worker exclusion, expected-archive binding, bounded retries and crash-after-commit replay. The integrated demonstration deliberately exits a worker process, resumes its recorded job, imports a following month and quarantines a conflicting batch. Real source approval, scheduler/backoff, distributed ownership, representative recovery and production orchestration remain open.

The sixth new data-platform increment adds [persisted research retry timing and pause controls](RETRY_SCHEDULING.md) through an explicit case-queue extension. Manual worker calls honor due times, bounded exponential backoff and pause without consuming attempts. Synthetic fault/test-clock checks verify policy persistence, not real elapsed contention, background supervision or a production scheduler installation. Existing cases are not automatically upgraded.

The seventh new data-platform increment adds a [bounded foreground synthetic ingestion runner](BOUNDED_INGESTION_RUNNER.md). It invokes eligible work, polls while retries wait, honours cooperative stop/pause, bounds each invocation and records latest local status. Real-clock demonstrations retain synthetic-only cases; no operating-system task or background service is installed. Supervision, independent health, authorized sources and representative recovery remain open.

The eighth new data-platform increment adds [read-only runner snapshot inspection and abrupt-exit recovery evidence](RUNNER_STATUS_INSPECTION.md). A real runner exits after a synthetic data commit; the inspector labels the orphaned snapshot without claiming process liveness, and a new invocation recovers through the import ledger. Freshness is not health or authentication, and no automatic recovery/monitoring service is installed.

The ninth new data-platform increment adds [offline synthetic batch/archive/ledger/row reconciliation](CASE_RECONCILIATION.md). Retained succeeded batches are reconstructed in new scratch state and every selected flight row is compared against a declared offline case, with queue/ledger bindings and before/after input hashes. It rejects changed copies without repairing them. This is reproducibility/consistency evidence using the existing importer, not independent parsing, source authentication, current health or a production acceptance gate.

## Data-science continuation

The first new data-science increment adds [point-in-time split preparation](TEMPORAL_PREPARATION.md). It revalidates feature availability, separates targets/provenance from model inputs, and excludes labels unavailable at each chronological cutoff. The synthetic demonstration does not read the frozen holdout or fit a model. Authorized data, grouped identity/cohort checks, independent experiment registration, train-only preprocessing and unused chronological evaluation remain open; earlier phases are not thereby accepted.

The second new data-science increment adds [train-only preprocessing](TRAIN_ONLY_PREPROCESSING.md): an explicit-column encoder/scaler fitted once on training rows and applied to future splits without refitting. Synthetic noninterference checks retain JSON state and sparse matrices; unseen origins do not expand the schema. No predictive model is fitted and frozen experiments remain unchanged. Authorized real data, cohort/group review, independent experiment/evaluation and lifecycle qualification remain open.

The third new data-science increment adds [development-only regression candidate selection](VALIDATION_REGRESSION_SELECTION.md). It records an explicit local protocol before synthetic fits, compares fixed Ridge candidates with a training-median baseline on validation MAE and retains selected coefficient/preprocessing bindings. Test partitions and extra holdout fields are refused. Protected registration, authorized real data, unused chronological test evaluation and model lifecycle qualification remain open.

The fourth new data-science increment adds [one-attempt synthetic holdout evaluation](SYNTHETIC_HOLDOUT_EVALUATION.md), under a separate subsequent-stage policy pinning frozen artifacts and cohort files. An exclusive local marker is consumed before holdout reads; only the validation-selected state and fixed baseline are scored, with no refit or repeat attempt in that directory. Toy-formula results are execution evidence, not independent airline accuracy. Protected/global authorization, genuine independent data and production qualification remain open.

PRs remain reviewable and unmerged until explicitly authorized. PR #1 covers the single-batch trace; PR #2 adds the five-month coverage audit. Keep later increments separate and declare any stacked-branch dependency. After an eventual merge, verify the final main revision and its own checks before considering deployment. Do not deploy a branch merely because its development tests passed.
