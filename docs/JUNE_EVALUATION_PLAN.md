# Frozen June evaluation plan

The existing delay-v2 model trained on January–March 2025, selected its settings and demonstration threshold in April, and evaluated May. Those months are already used. The next planned comparison is June 2025, strictly later than the registered model periods. This does **not** establish that no person or other experiment has previously inspected June.

`ml/june_evaluation_plan.json` prespecifies the target/cohort, frozen-model inference, constant training-prior baseline, metrics, research comparison, carrier/origin diagnostics and a day-cluster bootstrap design for loss differences. The bootstrap is a plan, not implemented or executed statistical evidence. Historical schedule snapshots and US-to-UAE transfer limitations remain. No calibration, refitting, model selection or threshold search is permitted in this comparison.

From the native research checkout, prepare a fresh private snapshot using the existing trusted model's explicit artifact fingerprint:

```powershell

```

The registrar validates the frozen plan fingerprint, copies only the registered local delay-v2 artifact/report through the existing trusted-copy helper, checks the recorded period groups, and freezes the report's numeric threshold and training prevalence. It never deserializes a model or accepts/opens a candidate archive. It checks the original source bytes and writes `plan.json`, `model/model.joblib`, `model/report.json` and `registration.json` into the new directory. Existing destinations, changed inputs, overlapping periods and invalid baselines are refused. A failure may retain a partial private model copy; keep it for inspection and do not treat a missing registration receipt as success. This is unsigned local consistency evidence, not independent artifact/source authentication.

The declared June source URL follows the project's existing BTS monthly URL pattern; availability, archive identity, source purpose/rights and row quality are not established by the registration command. At plan registration, only January–May archives were identified locally. A later data-admission step must obtain and validate the exact June archive **after the freeze**. Before candidate rows are opened, a future evaluator must implement and create an exclusive attempt receipt, retain failures, and prevent repeat evaluation. This registrar does not implement the evaluator or global single-use enforcement, and copying the same plan into another directory does not create another independent experiment.

No candidate rows or labels are read, no metrics or confidence intervals are computed, no new model is trained, and no data is imported into the active application database. The existing scenario API remains restricted to its documented January–May research window. This registration does not expand prediction serving or qualify any production requirement.

## Checkout-local single-attempt evaluator

`python -m ml.evaluate_june --admission .local/ADMISSION/admission.json --admission-sha256 EXACT_ADMISSION_SHA256 --output .local/NEW_EVALUATION --trusted-registered-model` is an explicit owner-invoked evaluation of the already trusted registered model. Joblib is executable serialization: the flag is required, inputs must match the pinned admission/registration/committed report, and the exact model bytes are captured before deserialization. No arbitrary model path or alternate month is accepted. The original plan JSON remains unchanged; its future-work wording records the status at the freeze.

Before any CSV member is opened, the evaluator exclusively creates and flushes `.local/evaluation-attempts/2025-06.json`. That fixed path prevents another admission/output directory or concurrent invocation from repeating June within this checkout. A failed attempt remains consumed; there is no reset or automatic retry. A partially written claim also stays retained and blocks another invocation. This is unsigned local enforcement, not protection against OS-owner edits, another checkout or previous external inspection. It does not establish a globally untouched holdout.

Within that attempt, the evaluator streams and exhausts the CSV, validates required unique header fields, shapes, finite values and actual June dates, and checks natural identities in a separate private scratch SQLite store. Identical duplicates are counted once; conflicting identities abort rather than being dropped. Exclusions prioritize cancellation, then diversion, then missing arrival targets. Full EOF/CRC validation must complete before inference. At most five million input rows and one million eligible rows are accepted; excess data fails instead of being sampled or silently truncated. A 300-second cooperative deadline is checked during row processing and between stages; native library calls are not forcibly interrupted.

The existing threshold and training prevalence stay frozen. Only the registered schedule-feature columns reach `predict_proba`; no fit, partial fit, calibration or threshold search occurs. Overall planned metrics, carrier/origin cohorts with at least 500 eligible records and both classes, and 1,000 seeded whole-flight-date cluster resamples are reported. Bootstrap loss/Brier differences are flight-weighted after resampling complete date clusters; percentile intervals are descriptive, with no independence, significance or UAE-transfer claim. A completed evaluation can fail the research comparison: `state=evaluated` means the experiment completed, not that a model was approved.

`report.json` retains successful or failed results; the immutable attempt points to the output. Controlled failure codes omit row values. Inputs are rechecked after scoring, and failures never authorize a new June attempt. The active application database/model and January–May scenario API are unchanged. Focused tests: `python -m unittest discover -s tests -p test_june_evaluation.py`; all classifiers and rows in these tests are synthetic, with no real June access. Actual counts, performance and uncertainty require a separate single native run and its retained receipt.
